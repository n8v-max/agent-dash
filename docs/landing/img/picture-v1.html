Why here and not in your other dashboards

The one place the cost of an attempt and whether it was accepted sit on the same row.

Usage dashboardssee that agents ran: lines accepted, messages, tokens, a leaderboard. No outcome per attempt.
Delivery dashboardssee what shipped: cycle time, DORA, allocation. They cannot see inside an attempt, and their ROI is a calculator over inputs you supply.
This dashboardprices every attempt, keys it to an issue and a person, and counts it only when its work was accepted. The join is native.

QuestionsAsked before the demo

Straight answers.

Do you claim engineers deliver more with agents?

No. Measuring that needs a baseline from before agents, and the window we observe is entirely agent-assisted. We give you your own cost per finished Job, month against month. The number you compare it with is yours.

Where does the cost figure come from?

It is attributed upstream by billing, per session, against token and machine rate cards, and stored on the row. This dashboard prices nothing. Seat fees are added at monthly grain and coarser.

What counts as a finished Job?

A Task with at least one accepted attempt. Each template defines its own criterion: a published pull request, a submitted review with an outcome, a commit landed on the default branch. A branch alone never counts.

Can I see individuals?

By default, everyone in the organisation sees everyone by name, on the same terms. There is no leaderboard, no percentile and no ordering presented as a verdict. Roles can restrict it, and the page loses rows, not features.

Is this a billing page?

No. It is not an invoice, a trace viewer, or a performance review tool. It is the unit economics of your agent work, with the waste inside it broken out.

How fresh is the data?

Every page carries an as-of stamp. Session rows are immutable once the session ends, so no figure ever changes after you have read it.
