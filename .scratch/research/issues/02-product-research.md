# Product research: JTBD, demo UX, metric framing for eng-team analytics

## Question

What jobs-to-be-done does an eng-team AI-agent analytics dashboard solve? What makes the /demo route feel like a "wow" moment in 30 seconds for an EM or CEO?

## Context

Landing hero is outcome-first: "Ship faster. Know why." Dashboard personas: Admin (EM/FinOps), Member (engineer), Viewer (leadership). The /demo route is public, SSR, uses fixture data — it IS the product pitch.

## Deliverable

A short brief covering:
1. Top 3 JTBDs for each persona (Admin, Member, Viewer)
2. What the "30-second wow" sequence looks like on /demo (which metric, which chart, which interaction)
3. How competitor dashboards frame similar metrics — and where this one should differ
4. Recommended metric labels that land for a non-technical CEO (avoid jargon)

Feeds: metric sign-off (03), empty-state design (06), fixture narrative (05), landing copy.
