# App shell, page toolbar, and URL-backed controls

## Goal

The header/toolbar shell (R-N3) and the control layer whose single source of truth is the query
string.

## Scope

**Shell.** Top header: product mark · nav (`/demo`, spend, work, people) · ellipsis (history,
projection, each with a one-line description) · account switcher. Below it a **sticky page
toolbar** holding that page's declared controls, period first; **absent** on pages declaring none.

- The header holds *who you are*; the toolbar holds *what is in the URL*. Keeping them visibly
  separate keeps the two kinds of state distinct.
- **No sidebar.** Four nav items plus an overflow do not fill one, and the seven-column people
  table and the acceptance small multiples both want the horizontal space.
- The account switcher re-issues the token and reloads **in place**, keeping the viewer on the
  current URL (R-A5), so the difference reads as *the same page with fewer rows*.

**Controls (R-C1–R-C5).**

- **Declared per page, not per chart.** Each page declares the dimensions its panels use; a control
  applies to every panel on that page using that dimension and to no others. **No page shows a
  control its panels cannot use, and no greyed control appears anywhere.** Declared sets are in
  `spec.md` § 5.
- **One parse/serialise module owns the schema** (R-T26). It parses `searchParams` into a typed
  validated set, **coerces or rejects invalid combinations rather than rendering them** — day grain
  over a range longer than two months is the named case — omits parameters equal to the page
  default, and exposes each page's declared set as data.
- **The query string is the single source of truth** (R-T25). No React state mirrors it, no context
  caches it.
- **Everything serialises**: period, grain, filters, roll-up level, subject, sort. A roll-up level
  changes a chart more than most filters do, so omitting it would break the share.
- **Navigation between pages drops control state** (R-C5, R-T27). Implemented by *not* carrying the
  query string into nav `href`s — the absence is the mechanism, so it needs a test rather than a
  comment.

## Done when

**T-C4, T-C5, T-C6, T-E5, T-E6** pass.

## Notes

type as the global `PageProps<'/route'>` helper — no import; it is generated by `next typegen`,
which is why `pnpm typecheck` runs typegen first.
