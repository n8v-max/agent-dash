# App shell, page toolbar, and URL-backed controls

## Goal

The header/toolbar shell (R-N3) and the control layer whose single source of truth is the query
string.

## Scope

**Shell.** Top header: product mark · nav (`/demo`, spend, work, people) · ellipsis (history,
projection, each with a one-line description) · account switcher. Below it a **sticky page
toolbar** holding that page's declared controls, period first; **absent** on pages declaring none.

- The header holds *who you are*; the toolbar holds *what is in the URL*. Keeping them visibly
  separate keeps the two kinds of state distinct.
- **No sidebar.** Four nav items plus an overflow do not fill one, and the seven-column people
  table and the acceptance small multiples both want the horizontal space.
- The account switcher re-issues the token and reloads **in place**, keeping the viewer on the
  current URL (R-A5), so the difference reads as *the same page with fewer rows*.

**Controls (R-C1–R-C5).**

- **Declared per page, not per chart.** Each page declares the dimensions its panels use; a control
  applies to every panel on that page using that dimension and to no others. **No page shows a
  control its panels cannot use, and no greyed control appears anywhere.** Declared sets are in
  `spec.md` § 5.
- **One parse/serialise module owns the schema** (R-T26). It parses `searchParams` into a typed
  validated set, **coerces or rejects invalid combinations rather than rendering them** — day grain
  over a range longer than two months is the named case — omits parameters equal to the page
  default, and exposes each page's declared set as data.
- **The query string is the single source of truth** (R-T25). No React state mirrors it, no context
  caches it.
- **Everything serialises**: period, grain, filters, roll-up level, subject, sort. A roll-up level
  changes a chart more than most filters do, so omitting it would break the share.
- **Navigation between pages drops control state** (R-C5, R-T27). Implemented by *not* carrying the
  query string into nav `href`s — the absence is the mechanism, so it needs a test rather than a
  comment.

## Done when

**T-C4, T-C5, T-C6, T-E5, T-E6** pass.

## Notes

`params` and `searchParams` are **Promises** in this Next. Await them, or use `use()`. Page props
type as the global `PageProps<'/route'>` helper — no import; it is generated by `next typegen`,
which is why `pnpm typecheck` runs typegen first.

## Comments

### 2026-09-08 — implemented (AFK build, wave 7)

All six gates green: `lint` (0 errors; the one warning is ticket 29's T-E4 TODO) · `typecheck` ·
`test` (**794**, up from 680) · `test:coverage` · `build` · `e2e` (**29**, up from 22).

`src/components/controls/schema.ts` is the single module owning parse, serialise, page paths and
period→range resolution (R-T26). The toolbar is driven by a `Record<ControlKey, renderer>` over
`DECLARED_CONTROLS`, so there is **no second list of controls** to fall out of step with R-C1.

**R-T25 is structural, not careful.** Every control is an `<a href>` — there is no `onChange`
anywhere in the control layer; the browser's navigation performs the write and the next server
render performs the read. And `src/components/controls/**` carries **no `"use client"`**, so every
module in it is a Server Component and `useState` is not in scope: the failure R-T25 names is not
expressible. That is **asserted rather than inspected** — the test reads the whole directory with
`import.meta.glob(..., {query: "?raw"})` and asserts no `"use client"` directive and no
`useState`/`useReducer`/`useEffect`/`useRef`/`useContext`/`createContext`/`useSearchParams`/
`useRouter`, so a new module dropped into the directory is covered automatically. The one Client
Component in the shell is `shell-nav.tsx`, which uses `usePathname()` for the active highlight
(a layout does not re-render on soft navigation) and holds no state.

**T-C4** uses a `CASES` table with one entry per member of `CONTROLS`, plus a test asserting the
case set *equals* `CONTROLS` — so a control added without a URL representation fails there. Bare
route = page defaults on all six pages, and `controlHref(defaults) === pathFor(page, org)`.
**T-C5** coerces `?grain=day` over the 150-day window to month and never serialises day; a link
that *widens* the period re-coerces, because the coercion runs on every href rather than only on
parse. **T-C6** is table-driven over the six pages, asserting the rendered set equals
`DECLARED_CONTROLS[page]` *in declaration order*, period first, nothing greyed — unavailable grains
are **absent, not disabled**. **T-E5** asserts both the outcome and the mechanism: no nav `href`
contains `?`. **T-E6** switches account from `/demo/people?sort=cost` and lands on the same URL with
rows 20 → 1 and a re-issued `httpOnly` cookie.

**The toolbar is absent, not empty, on `/demo/projection`**: `PageToolbar` returns `null` before
creating any element, so there is no bar, no border and no reserved height.

**The account switcher preserves the URL via `Referer`, deliberately.** A hidden field written at
render time was rejected: the layout renders once and is preserved across soft navigations, so the
field would be right on the first document and stale afterwards, whereas the browser recomputes
`Referer` per submission. The endpoint honours it only when same-origin *and* under the account's
own org path; validation covers other origins, protocol-relative escapes, another Organization's
path, and `/demonstration/...` prefix collisions.

### The account switcher names Roles, not Members — and T-E4 is why

Listing the other account's full name in the header put a **named individual in the payload of a
viewer holding no identifying scope over them**, and T-E4 caught it. R-A5 requires the token
re-issue and the in-place reload; it does not require the menu to name the person. The trigger still
shows the viewer's own name, which R-A3.1's universal `self` grant covers. This is the access model
catching a real leak in ordinary UI work, which is the thing it was built for.

### Four arguments recorded, none re-decided

1. **Period values are unspecified.** § 5 names a Period control and never enumerates it. Offered as
   "All data" (the observation window, the default) plus one option per calendar month the window
   touches — a month is the unit R-M5 bills in and R-N6 reports, and a single month is short enough
   for R-M11 to offer day grain, so period and grain visibly interact instead of one silently
   constraining the other. Consequence: selecting a single month on `/demo` leaves one bucket, so
   R-M12 suppresses the change figure; the default preserves R-N7's current-vs-previous reading.
2. **`subject` offers three values, not two.** R-C1 writes "subject (Team or Member)" but
   `defaultControls` sets `subject: "organization"`, and R-C4 requires a control to be able to show
   its own default.
3. **Request-time `now` was unowned by any spec or ADR.** `src/data/clock.ts` records the decision:
   the wall clock clamped to midday UTC on the window's last day. R-E1 says there is no designed
   zero-data state, and an unclamped clock hands the artefact one the day after the window closes.
4. `/demo/people` and `/demo/history` render their tables now, because T-E6's "fewer rows" is not
   assertable without rows on a page. The other four carry a placeholder naming the panels wave 9
   builds.
