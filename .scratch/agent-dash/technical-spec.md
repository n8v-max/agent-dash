# Technical implementation spec — agent-dash

Status: draft for review
Written: 2026-09-07
Reads with: `spec.md` (requirements), `testing-spec.md` (step 3), `CONTEXT.md` (vocabulary)

**This spec draws the seam ticket 09 left undrawn**, recorded as
[ADR-0006](../../docs/adr/0006-computation-rendering-seam-is-a-viewmodel.md). Ticket 09 was closed `wontfix` with a
default position assembled from other tickets, and recorded its cost plainly: *"Nobody has decided
where the seam between metric computation and rendering sits. The intent — pure functions over
fixture rows, isolated from React — is implied but is not architecture until someone draws it."*
Section 3 draws it. That is the single highest-leverage decision in this document, and everything
in § 4–§ 8 follows from it.

**Verified against the installed framework, not from memory.** `CLAUDE.md` warns that this Next.js
differs from training data. Every framework claim below was checked against
`node_modules/next/dist/docs/` on 2026-09-07. Where a convention has changed, the change is called
out inline.

**R-T1 — Turbopack is mandatory.** Both open Next × Recharts 3 blockers
([recharts#6117](https://github.com/recharts/recharts/issues/6117),
[#6316](https://github.com/recharts/recharts/issues/6316)) are webpack-specific. Next 16 makes
Turbopack the default, so this holds without configuration — but it must not be turned off.

**R-T2 — shadcn is scaffolded from a `v4` or `base-*` style.** This is a hard requirement and a
setup-time constraint, not a defect to encounter later. The legacy `default` / `new-york` styles
pin `recharts@2.15.4`, npm-marked **deprecated** — the same dead 2.x branch that disqualified
Tremor in ticket 04. Landing there would silently reverse ticket 14's decision. Verify
`components.json` and the resolved `recharts` version immediately after `shadcn init`.

**R-T3 — Recharts must be pinned exactly**, not caret-ranged, so a transitive bump cannot cross
the 2.x/3.x boundary unobserved. **This is outstanding**: `package.json` currently carries
`"recharts": "^3.10.1"`. Ticket 17 pins it.

### 1.1 Framework conventions that differ from older Next

Checked against `node_modules/next/dist/docs/`. An implementer working from memory will get these
wrong.

- **`middleware.ts` is deprecated and renamed `proxy.ts`** (Next 16). Same functionality, new file
  and export names. Codemod: `npx @next/codemod@canary middleware-to-proxy .`. This spec uses
  `proxy.ts` throughout.
- **`params` and `searchParams` are Promises.** Pages must `await` them, or use React's `use()`.
- **`PageProps<'/route'>` and `LayoutProps<'/route'>` are global type helpers** — no import. They
  are generated by `next typegen`, which is why `pnpm typecheck` runs `next typegen && tsc
  --noEmit` (commit `e6b2111`). The committed `src/app/layout.tsx` already uses `LayoutProps<"/">`.
- **Route Handlers type their context with the global `RouteContext` helper.**

**R-T4 — Proxy is an optimistic check only, never the authorization boundary.** The Next docs are
explicit that Proxy *"should not be used as a full session management or authorization solution"*.
This aligns with ADR-0003 and R-A6, which put enforcement in the data layer. `proxy.ts` does the
cheap redirect (no token → `/sign-in`); the real gate is § 5.2.

## 3. The seam

This is ticket 09's open question, answered.

### 3.1 Three layers, two boundaries

```
  committed JSON
        │
        │  ── boundary 1: parse + validate. The only I/O in the app.
        ▼
  src/data/load.ts          →  fixture rows, typed, hidden sessions already removed
        │
        ▼
  src/domain/**             →  PURE FUNCTIONS. rows in, numbers out.
        │                       permission filter · bucketing · aggregation ·
        │                       comparability · capping · change
        │
        │  ── boundary 2: the ViewModel. Plain, serialisable, fully resolved.
        ▼
  src/data/queries.ts       →  ViewModel  (the façade Server Components call)
        │
        ▼
  src/app/** + components/  →  RENDERING ONLY. Receives ViewModels as props.
```

**R-T6 — Boundary 2 is a ViewModel, and it is the seam.** A panel component receives a fully
resolved ViewModel and renders it. It does not receive `AgentSession[]`. It does not filter,
bucket, sum, sort, rank, cap or compare. Every number a component displays was computed in
`src/domain/` and arrived as a property.

**Why a ViewModel rather than "components call pure helpers".** The weaker version — components
import `aggregate()` and call it in render — leaves the aggregation *reachable* from React, which
means it gets tested through React, which is the exact failure ticket 09 was worried about. Making
the boundary a **data structure** rather than a **function call** means a component physically
cannot compute; there is nothing in scope to compute with. That is what converts "pure functions
over fixture rows" from an intent into architecture.

**What a ViewModel contains.** Everything needed to render, and nothing else:

```ts
type ChartViewModelExtras = {
  stackable: boolean       // R-V1 — true only where the grouping partitions the measure
}

type SeriesViewModel = {
  key: string              // stable series identity — NEVER an array index
  label: string            // display label, already resolved (Member name, model family, ...)
  colorVar: `--chart-${1|2|3|4|5}`
  points: { bucket: string; value: number | null }[]
}

type ChartViewModel = {
  title: string
  rollUpLevel: string      // drives the aria-label (R-X2)
  buckets: { key: string; label: string; partial: boolean }[]
  series: SeriesViewModel[]
  other: { holds: string[] } | null      // populated only when the cap engaged (R-V4)
  overlapNote: string | null             // populated for Team groupings (R-V3)
  stackable: boolean                      // R-V1 — domain-supplied, never a styling choice
  empty: boolean                          // drives the R-V9 fallback
  mirror: { columns: string[]; rows: (string | number)[][] }   // R-X1
}
```

**R-T7 — The table mirror is built in the domain layer, not derived in the component.** If the
component derived it from the series it would be a second rendering of the same array and would
prove nothing. Built upstream, it is an independent statement of what the chart claims, and
therefore a real assertion target (`testing-spec.md` § 4.2).

**R-T8 — `key` is a domain-supplied stable identity, never an array index.** shadcn's default
legend uses `key={index}`; ticket 14 deferred that patch to encounter. With `key={index}` live,
React reconciles "Team A" into "Team B" in place across a roll-up switch. The ViewModel carrying an
explicit stable `key` is what makes the patch mechanical when it is encountered, and
`testing-spec.md` T-C3 is the test that catches it.

### 3.2 Where each rule is enforced

Placing a rule in the wrong layer is how it stops holding. Explicitly:

| Rule | Layer | Why there |
|---|---|---|
| Hidden-session exclusion (R-M2) | `data/load.ts`, once, at parse | An invariant of the dataset, not a query option. Nothing downstream can forget it |
| Permission filter (R-A6) | `domain/access.ts`, before aggregation | A below-grant figure must never reach a payload, so it must never reach a sum |
| Period bucketing (R-M10) | `domain/periods.ts` | Pure `(rows, timezone, grain)` |
| Non-additive Team roll-up (R-V3) | `domain/aggregate.ts` | The overlap note is computed with the total, so they cannot disagree |
| Per-capita denominator (R-M14) | `domain/aggregate.ts` | Excluding service accounts is arithmetic, not presentation |
| Comparability intersection (R-M8) | `domain/comparability.ts` | Data, evaluated in the data layer; the UI consumes the allowed set to build its controls |
| Series cap + ordering (R-V4, R-V5) | `domain/series.ts` | Ranking across the whole range, then bucketing, is impossible to do correctly per-bucket in a component |
| Stack-only-partitions (R-V1) | `domain/` supplies `stackable: boolean` on the ViewModel | Whether a grouping partitions the measure is a domain fact, not a styling choice. A component must not decide it |
| Change floor (R-M12) | `domain/change.ts` | One rule, one place |
| Day-grain restriction (R-M11) | `domain/periods.ts` + control validation | Rejected at parse of the URL, so an invalid state is unrepresentable |
| "Estimated" / "illustrative" labels (R-V8) | `components/` | Genuinely presentational; the domain layer carries no copy |

## 4. Domain types

**R-T9 — Types mirror `CONTEXT.md` exactly, including the UI aliases.** There are exactly two:
`Task` in code, "Job" in copy; `WorkType` in code, "template" in copy. Each alias lives in a display
map, never in a type name. **`Repository` has no alias** — the "Project" alias was dropped from the
glossary on 2026-09-07 (`spec.md` § 11 C-series discussion): "Repository" is the word the audience
uses, and ADR-0004 makes repository *names* load-bearing precisely because a reader reads them as
repositories.

**R-T10 — `Task` the domain entity must not be confused with any task-runner concept.** The map
flags this collision; it is noted here because the term appears throughout.

Shape, abbreviated to the load-bearing fields:

```ts
type AgentSession = {
  id: string
  parent_session_id: string | null   // the root this was spawned by; null on a root (R-M19)
  started_at: string          // ISO 8601 with offset
  ended_at: string
  member_id: string
  repository_id: string
  work_type: WorkTypeKey
  task_key: string            // "owner/repo#number" — external, never synthetic
  execution_mode: 'interactive' | 'headless'
  machine_spec: 'general' | 'compute' | 'memory' | 'storage'
  accepted: boolean           // the ONLY outcome field (R-M3)
  hidden: boolean             // infra-failed; stripped at load (R-M2)
  prompt_count: number
  cost: number                // ATTRIBUTED upstream, stored. Never derived here (R-M4)
  interactive_duration_s: number
  idle_duration_s: number
  afk_duration_s: number
  machine_allocation_duration_s: number   // == sum of the three spans, asserted
  artefacts: Partial<Record<ArtefactKind, number>>
  token_usage: { model_id: string; uncached_input: number; cache_read: number;
                 cache_write: number; output: number }[]
}
```

**R-T11 — `cost` is read, never computed.** There is no pricing function in `src/domain/`. The
rate cards are generator inputs (§ 6) and, for the token card only, display data. ADR-0005.

**R-T12 — The three duration spans sum exactly to `machine_allocation_duration_s`**, asserted by
the generator on every row and re-asserted as a fixture invariant test. It survives the R-T37
roll-up because all four fields are summed together, not three of them.

**R-T37 — The session tree is validated and folded once, at parse** (R-M19, ADR-0008). Added
2026-09-09 (ticket 48).

*Validated*: a child that names a root which does not exist, is not itself a root, disagrees with
any of the five labels it inherits, carries `accepted`, or is visible under a hidden root is a
**FixtureFault** — the same fault model as every other shape violation. The rules live in
`src/domain/sessions.ts` as one expression (`childFaults`), so the loader and the fixture invariant
test cannot come to different conclusions about what a valid child is.

*Folded*: `load.ts` returns **roots**, each carrying its children's cost, tokens and duration spans,
plus a separate `childSessions` map keyed by root id. Both happen on the same line as R-M2's hidden
strip: a per-query fold is a fold somebody eventually forgets, and the one query that wants the raw
children — `/demo/history` — asks for the map by name.

The folded `cost` is rounded to whole cents. That is not the application pricing anything (R-M4):
`4.23 + 0.09` is `4.32` in the unit money is denominated in and `4.319999999999999` in binary, and
the row this produces stands in for a stored row on every surface that reads one.

## 5. Auth, tenancy, enforcement

### 5.1 Token issuance

**R-T13 — `POST /api/session` issues a JWT for one of the two seeded accounts** and sets it as an
`httpOnly`, `sameSite=lax`, `secure` cookie. `DELETE` clears it. `/sign-in` posts to it; the header
switcher posts to it and reloads in place (R-A5).

**R-T14 — The JWT is signed with the env secret `AUTH_JWT_SECRET` and carries `{ member_id, org_slug }` only.** Grants
are **not** in the token — they are resolved server-side from the Member's Role. A token carrying
its own grants is a token that can be edited to widen them.

The secret is read server-side only and is **never** `NEXT_PUBLIC_`-prefixed: a signing key
serialised to the browser forges tokens for anyone who opens devtools. It is absent by design from
`.env.example` (empty key, generation command in the comment), present in `.env.local` for dev, a
fixed non-production literal in CI, and set in the Vercel dashboard for production. **Read it once
at module load and throw if it is missing or under 32 bytes** — HS256 requires 32, and a server
that boots without a key would otherwise fail at first sign-in instead of at deploy.

### 5.2 Enforcement

**R-T15 — Two checks, in this order, and only the second is authoritative.**

1. **`proxy.ts` — optimistic.** No cookie on a `/[org]/**` path → redirect to `/sign-in`. Cheap,
   and per R-T4 explicitly *not* the authorization boundary.
2. **`src/app/[org]/layout.tsx` — authoritative.** Verifies the JWT, compares `org_slug` against
   the `[org]` path segment, and calls `notFound()` on mismatch or unknown slug. **404, not 403**
   (R-A7): a 403 confirms an Organization exists.

**R-T16 — The verified viewer is resolved once per request and threaded into every query.**
`queries.ts` takes `(viewer, params)`; there is no query function that can be called without a
viewer. An unfiltered query is not merely discouraged — it does not typecheck.

**R-T17 — The permission filter runs before aggregation, never after.** Filtering a computed
aggregate leaks by arithmetic; filtering rows does not.

**R-T18 — Nothing below grant is serialised to the client.** Server Components render with the
filtered ViewModel; client components receive only the ViewModel. A reviewer opening devtools on
the restricted account must find no ungranted figure in the RSC payload. This is asserted directly
(`testing-spec.md` T-E4).

## 6. Fixtures

**R-T19 — Datasets are shaped by where they would really come from.**

| Dataset | Source it imitates | Shape |
|---|---|---|
| Sessions | Platform events | One JSON file per `(repository × work_type)`, rows ordered by timestamp. **All 25 exist**; empty pairs hold `[]` (R-D19) |
| Members, Teams, Repositories, Tasks | Mocked GitHub API | GitHub field names (`login`, `email`, `full_name`, `id`) with a **simplified envelope**: no pagination, no `_links`, no unread fields |
| WorkTypes, Models, rate cards, Organization | Mocked internal API | Serialised as-is |

A faithful GitHub envelope would need a real adapter layer, which is exactly the ground ticket 13
was closed `wontfix` on.

**R-T20 — The generator is committed, seeded, and its output is committed.** Tests read the
committed output and **never** run the generator: a test that regenerates its own input tests the
generator, not the app.

**R-T21 — CI asserts the committed output still matches the seed.** Regenerate into a temp
directory and diff. This is the only place the generator runs in CI.

**R-T22 — The generator holds both rate cards and prices every session**, writing a `cost` field
(ADR-0005). The token card is additionally serialised for display; the compute card is serialised
for the generator's own use and rendered nowhere (R-N11).

**R-T22.1 — The fan-out is generated last, from finished rows** (R-D21). Every stage upstream of
it — the schedule, the Task shapes, the cell assignment, the model draw, the hidden rows — runs as
it did before children existed, so the roots it produces are byte-identical apart from the schema's
new field, and child ids continue the sequence rather than renumbering it. That is what makes
ADR-0008's own claim checkable: the headline figures move by the roll-up because the roots did not
move at all.

**R-T23 — The generator asserts its own invariants as it writes** — span sums (R-T12), the
required distributions (R-D6 through R-D17), the presence of every required edge case. A generator
that silently produces a fixture missing the 90+ day bucket is worse than one that fails loudly.

**R-T24 — The roster and token rate card are fixed by ADR-0007.** Ticket 16's check was run on
2026-09-07: three of its seven strings did not exist, a fourth was no longer `frontier`, and the
card's "exactly 200×" turned out to be manufactured by errors at both ends — the real spread across
that roster was ~20×. The shape survived (7 models, 3 vendors, tiers 2/2/3, cross-vendor tiers,
one authored input per model); the contents were replaced.

The generator prices from ADR-0007's card. **Input prices are real as verified; the other three
classes derive by uniform ratios (0.1× / 1.25× / 5×), which are Anthropic's and are applied across
all three vendors** — so the card stays illustrative and keeps that label. Frontier over fast is
exactly 200× with no adjustment.

## 7. URL state

**R-T25 — The query string is the single source of truth for control state.** No React state
mirrors it, no context caches it. Controls read from `searchParams` and write with the History API.

**The guarantee is structural, and `components/controls/` is where it is structural.** No module in
that directory carries `"use client"`, so `useState` is not in scope there and a mirror of the URL
is not expressible; `page-toolbar.test.tsx` asserts the absence over the whole directory rather
than over a diff. `/demo/history`'s date range is the one control that needs a change event to
apply itself (R-N20), and its handler therefore lives in **`components/forms/`** rather than being
bought at the price of that guarantee. It holds no state either — it reads the form element the
event handed it, checks validity and submits — so the rule above is untouched by it.

**R-T26 — One parse/serialise module owns the schema**, in `components/controls/`. It:

- parses `searchParams` into a typed, validated control set;
- **coerces or rejects invalid combinations rather than rendering them** — notably day grain over
  a range longer than two months (R-M11, A3);
- omits parameters equal to the page default, so a bare route is the canonical short form (R-C4);
- exposes each page's declared control set as data (R-C1), so a page cannot render a control its
  panels do not use.

**R-T27 — Navigation between pages drops control state** (R-C5). Implemented by not carrying the
query string into nav `href`s — the absence is the mechanism, so it needs a test (T-E5) rather than
a comment.

## 8. Chart layer

**R-T28 — One `ChartFrame` wraps every chart** and is responsible for exactly four things: the
`aria-label` naming the roll-up level (R-X2), Recharts' `accessibilityLayer` (R-X3), rendering the
`mirror` as a visually-hidden `<table>` (R-X1), and the R-V9 empty fallback. No panel does any of
these itself.

**R-T29 — Charts under test render at fixed numeric `width`/`height`, not `initialDimension`.**
This settles the one item ticket 09 left genuinely open. Ticket 04 found that shadcn's
`initialDimension` win evaporates the moment `vitest.setup.ts` polyfills `ResizeObserver`, and that
the resulting failure is **confusing rather than loud**. Fixed numeric dimensions need zero mocks
and do not interact with setup files. The cost — test render dimensions differ from production — is
accepted and is invisible to every assertion this suite makes, because every assertion goes through
the mirror rather than through SVG geometry.

**R-T30 — `ChartConfig` is built from the ViewModel's series**, so the config and the rendered
series cannot drift. Four series plus "Other" fills `--chart-1..5` exactly; nothing can request a
sixth colour (R-V7), so the silent transparent-series failure is unreachable by construction.

**R-T31 — The roll-up spike runs first, before any panel is built.** Ticket 14 names it the
cheapest available risk reduction and the specific thing that would falsify the charting decision:
flip one chart between 20 and 4 series and watch the legend re-derive. Observable Plot's accessor
model would have removed this bug class structurally; shadcn/Recharts keeps it, and this is the
cost being paid. It is ticket 18 in the plan.

**R-T32 — Day-one patches are applied on encounter, not at setup**, with R-T2 as the sole
exception. Patch 2 (stale `.recharts-cartesian-axis-tick_text` selector), patch 3 (`key={index}`
legend keys) and patch 4 (blank-mount guard, shadcn-ui#8547) are deferred. Two of the three fail
silently, which is why T-C3 exists.

## 9. Build, quality gates, CI

### 9.1 Existing, already committed

`pnpm lint` · `pnpm typecheck` (`next typegen && tsc --noEmit`) · `pnpm test` · `pnpm test:coverage`
· `pnpm e2e`. Husky + lint-staged run `eslint --fix` on staged TS. Coverage thresholds are
statements 80 / branches 75 / functions 80 / lines 80, with route shells excluded because they
compose and carry no logic worth a unit test.

### 9.2 To add

**R-T33 — An ESLint boundary rule enforcing R-T5.** `no-restricted-imports` in an override for
`src/domain/**`, forbidding `react`, `next`, `next/*`, `node:fs`, and relative paths escaping into
`../data`, `../app`, `../components`. Without it, the seam is a convention, and conventions decay.

**R-T34 — A raised coverage threshold for `src/domain/**` specifically.** The global 80% is a floor
for a codebase that includes glue. The domain layer is pure functions with no I/O and no framework,
so its bar is **95% statements / 90% branches**. Test coverage is one of three grading criteria,
and a uniform threshold lets high coverage of trivial rendering code mask thin coverage of the
arithmetic that actually decides what the product claims.

**R-T35 — The fixture-seed check (R-T21) is a CI job**, failing the build on drift.

## 10. Performance

**R-T36 — No pagination, virtualisation, streaming or memoisation beyond React's defaults.** 167
days at session grain across 20 Members is ~10,900 rows — still tractable server-side per request:
`readDataset()` takes 75 ms and the whole of `/demo/spend` resolves in 217 ms p95 (measured
2026-09-10, ticket 66; both are linear in the row count and neither has a knee). Ticket 10 closed
the performance envelope on ~750 rows and found the live constraint to be the opposite one: **too
few rows per bucket**, which is why R-M11 restricts day grain rather than why anything needs
optimising. Ticket 66's volume settled that constraint and did not create the other one;
[ADR-0009](../../docs/adr/0009-scale.md) supersedes this rule at volume and now carries the
re-measured budget.

`/demo/history` paginates client-side at 50 for readability, not for performance.

## 11. Risks

| Risk | Exposure | Mitigation |
|---|---|---|
| shadcn scaffold lands on a legacy style and pins deprecated `recharts@2.15.4` | Silently reverses ticket 14 | R-T2 + R-T3, verified immediately after init |
| `key={index}` legend reconciles the wrong series across a roll-up switch | Silent, visible only as wrong colours | R-T8 stable keys + T-C3, and the R-T31 spike runs first |
| The seam erodes — a component starts computing | The thing ticket 09 was worried about | R-T5 enforced by lint (R-T33), plus the ViewModel giving components nothing to compute with |
| Aggregation bugs in non-additive Team roll-ups | The product asserts a wrong number confidently | The four ADR-0005 replacement targets are first-class unit tests (`testing-spec.md` § 3.2) |
| Fixture drifts from committed output | Tests pass against data the app does not ship | R-T21 CI check |
| Model version strings are stale | Cosmetic, but reads as carelessness | R-T24, before the fixture ships |
